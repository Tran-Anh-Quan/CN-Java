3. MÔ HÌNH PHÂN QUYỀN (RBAC - Role-Based Access Control)
================================================================================

3.1. CÁC VAI TRÒ (ROLES)
-------------------------
- ROLE_ADMIN  : Quản trị viên - có toàn quyền
- ROLE_STAFF  : Nhân viên - có quyền nghiệp vụ
- ROLE_USER   : Người dùng - chỉ có quyền cá nhân

3.2. BẢNG users
---------------
- id          : Primary Key
- username    : Tên đăng nhập (unique)
- password    : Mật khẩu (đã mã hóa BCrypt)
- fullName    : Họ tên đầy đủ
- email       : Email liên hệ
- active      : Trạng thái (true = hoạt động, false = bị khóa)
- createdAt   : Ngày tạo

3.3. BẢNG roles
---------------
- id          : Primary Key
- name        : Tên vai trò (ROLE_ADMIN, ROLE_STAFF, ROLE_USER)
- description : Mô tả vai trò

3.4. BẢNG user_roles (Many-to-Many)
-----------------------------------
- user_id     : Foreign Key -> users
- role_id     : Foreign Key -> roles

3.5. BẢNG audit_logs
--------------------
- id          : Primary Key
- username    : Tài khoản thực hiện
- action      : Hành động (LOGIN, LOGOUT, ADMIN_EDIT, STAFF_ACCESS, ...)
- details     : Chi tiết hành động
- createdAt   : Thời gian

4. CƠ CHẾ XÁC THỰC (AUTHENTICATION)
================================================================================

4.1. QUY TRÌNH ĐĂNG NHẬP
--------------------------
1. User truy cập /login -> AuthController.showLoginForm()
2. User nhập username/password -> POST /login
3. AuthService.authenticate() kiểm tra:
   - Tài khoản tồn tại?
   - Mật khẩu đúng? (so sánh BCrypt hash)
   - Tài khoản có bị khóa? (active = true?)
4. Nếu thành công: Lưu User vào Session -> chuyển đến Dashboard
5. Nếu thất bại: Hiện thông báo lỗi

4.2. MÃ HÓA PASSWORD (BCRYPT)
------------------------------
- Password không lưu plain text
- BCrypt.hashpw(password, BCrypt.gensalt()) để mã hóa
- BCrypt.checkpw(input, stored) để kiểm tra
- Mỗi lần hash khác nhau (salt ngẫu nhiên) nhưng đều verify được

4.3. SESSION
-------------
- HttpSession lưu "currentUser" sau khi đăng nhập
- Session timeout: mặc định 30 phút
- Logout: session.invalidate()

5. CƠ CHẾ PHÂN QUYỀN (AUTHORIZATION)
================================================================================

5.1. FILTER (BỘ LỌC)
---------------------
Filter là "người gác cổng" đứng trước request.

a) AUTHENTICATION FILTER
   - Áp dụng: /dashboard, /admin/*, /staff/*, /user/*
   - Kiểm tra: Đã đăng nhập chưa?
   - Nếu chưa: Redirect về /login
   - Nếu rồi: Cho qua

b) AUTHORIZATION FILTER
   - Áp dụng: /admin/*, /staff/*, /user/*
   - Kiểm tra: Có quyền không?
   - /admin/*  : Cần ROLE_ADMIN
   - /staff/*  : Cần ROLE_ADMIN hoặc ROLE_STAFF
   - /user/*   : Cần đăng nhập (bất kỳ role nào)
   - Nếu không có quyền: Forward đến /error/403.jsp

5.2. ẨN/HIỂN MENU THEO ROLE
---------------------------
Trong header.jsp và dashboard.jsp dùng JSTL <c:if>:
   
   <c:set var="isAdmin" value="false" />
   <c:set var="isStaff" value="false" />
   <c:forEach var="r" items="${sessionScope.currentUser.roles}">
       <c:if test="${r.name == 'ROLE_ADMIN'}"><c:set var="isAdmin" value="true" /></c:if>
       <c:if test="${r.name == 'ROLE_STAFF'}"><c:set var="isStaff" value="true" /></c:if>
   </c:forEach>

   <!-- Menu chỉ hiện khi có quyền -->
   <c:if test="${isAdmin}">
       <li><a href="/admin/users">Quản Lý User</a></li>
   </c:if>

   <c:if test="${isAdmin || isStaff}">
       <li><a href="/staff/dashboard">Nghiệp Vụ</a></li>
   </c:if>

5.3. BẢO VỆ 2 LỚP
------------------
- LỚP 1: Filter bảo vệ URL (ngăn truy cập trực tiếp)
- LỚP 2: Menu ẩn theo role (UI không hiện option không có quyền)

9. CÁC THÀNH PHẦN QUAN TRỌNG CẦN NẮM
================================================================================

9.1. @WebFilter
---------------
- Annotation đánh dấu Filter
- urlPatterns: các URL mà Filter áp dụng
- Thứ tự Filter: theo alphabetical order của class name

9.2. HttpSession
----------------
- Lưu trữ thông tin user đã đăng nhập
- session.getAttribute("currentUser") -> lấy user
- session.invalidate() -> đăng xuất

9.3. RequestDispatcher.forward()
---------------------------------
- Chuyển tiếp request đến trang khác (cùng server)
- Giữ nguyên URL trên trình duyệt

9.4. Response.sendRedirect()
----------------------------
- Chuyển hướng đến URL mới
- URL trên trình duyệt thay đổi

9.5. JSTL <c:if>
----------------
- Taglib: <%@ taglib prefix="c" uri="jakarta.tags.core" %>
- Kiểm tra điều kiện hiển thị nội dung

9.6. BCrypt
-----------
- Thuật toán hash password mạnh
- Có salt ngẫu nhiên
- Chống rainbow table attack

10. CÂU HỎI THƯỜNG GẶP
================================================================================

Q1: Tại sao cần Filter?
A: Filter giúp bảo vệ URL ngay cả khi user truy cập trực tiếp (không qua menu).

Q2: Tại sao cần ẩn menu?
A: UX tốt hơn + phòng trường hợp Filter bị bypass.

Q3: BCrypt hash có giải mã được không?
A: Không! BCrypt là one-way hash. Chỉ verify được, không revert được.

Q4: Session vs Cookie?
A: Session lưu server-side, Cookie lưu client-side (session ID).

Q5: Audit log lưu ở đâu?
A: Lưu trong bảng audit_logs trong database MySQL.
